# Frozen benchmark requests

The four JSON files in this directory are the exact OpenAI-compatible request bodies sent to the loopback server. They use alias `edge0_145b`, streaming with `stream_options.include_usage`, and pinned sampling values (`temperature: 0`, `top_p: 1`, `top_k: 20`, `presence_penalty: 0`, `frequency_penalty: 0`, `reasoning_budget_tokens: 128`). Prefill requests cap generation at one token; chat and agent requests cap it at 512. Their hashes are in [fixtures.sha256](fixtures.sha256), and token targets and provenance are in [fixture-metadata.json](fixture-metadata.json).

The 4K and 16K user messages come from Edge0 v0.2.0's Strata `standard-v1` performance prompt fixtures. The [pinned upstream bundle](https://github.com/Edge0-AI/Edge0/tree/v0.2.0/edge0-strata/bench/prompts/standard-v1) contains the source fixtures. See the [Strata MIT notice](../../STRATA-FIXTURES-LICENSE). Their frozen input counts are 4,093 and 16,386 tokens after the benchmark tokenizer and template, respectively. The runner's usage and timing output remains authoritative for the actual measured count.

The chat request asks for an 800-word library explanation with a 512-token cap. A smoke request with no reasoning budget consumed all 512 tokens in hidden reasoning and produced no answer, so the frozen requests set a 128-token reasoning budget to leave room for visible output. The chat fixture follows this recipe's requested workload and differs from Strata `standard-v1`'s short hash-table prompt. The agent request is an explicitly labeled approximation: it supplies a toy CSV parser and failing quoted-comma result as serialized tool messages, then asks for a patch through one local `submit_patch` schema. The model's generated tool call is captured as output data; no external tool is run.

Each request body is byte-identical across its three repetitions. The prefill trials start a fresh serving process each time, so a repeated prefix cannot be served from the prior request's conversation cache. The chat and agent trials also use fresh serving processes. Raw SSE, extracted events, usage, finish reasons, timings, response text/tool-call deltas, and client TTFT are saved per trial by [record_trial.py](../../scripts/record_trial.py). No benchmark result should be inferred from the expected/frozen token counts when the engine reports an actual count.
